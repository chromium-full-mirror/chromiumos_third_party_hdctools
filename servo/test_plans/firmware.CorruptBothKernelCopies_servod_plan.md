# Servod Test Plan: firmware.CorruptBothKernelCopies

This test plan emulates the hardware-level interactions of the `firmware.CorruptBothKernelCopies` Tast test.
It was automatically generated by extracting the `GET` and `SET` commands from a successful test run.

## Execution Parameters

To execute this test plan across different environments, the agent must dynamically inject the following variables:
* `${BOARD}`: The target ChromeOS board (e.g., `volteer`).
* `${MODEL}`: The target ChromeOS model (e.g., `delbin`).
* `${IMAGE_URL}`: The download path or URL for the ChromeOS test image or firmware archive. Depending on the environment, this could be a local path or a Google Cloud Storage URI (e.g., `gs://chromeos-image-archive/${BOARD}-release/RXXX-YYYY.Z.0/`).

## Firmware / Image Links

* When emulating this test, the agent needs to acquire the specific firmware or OS image required for the test variations.
* For tests like `FWAutoupdate`, download the older firmware archive from `gs://chromeos-image-archive/${BOARD}-firmware/` and stage it on the DUT prior to executing the servod commands.

## Prerequisites

1. **Hardware setup:** A DUT connected to a Servo (v4/v4.1 + CCD or Micro).
2. **Test Build:** Ensure the DUT is running an appropriate test-signed image located at `${IMAGE_URL}`.
3. **Environment:** If the test requires specific hardware states (e.g., AC power disconnected for battery tests), manually configure the physical environment before running this plan.
